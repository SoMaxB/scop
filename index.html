ANTES DEL PRIMER FRAME

La carga no necesita ventana.

main primero interpreta el OBJ, centra sus posiciones y carga el PPM. Solo después crea el contexto OpenGL 3.3 Core con GLFW, carga las funciones GL y compila los shaders.

Los datos de la malla se suben una vez con GL_STATIC_DRAW. Girar el objeto no reescribe todos sus vértices en la CPU: cambia la matriz enviada al shader.

CADA FRAME / src/main.c
tiempo actual − tiempo anterior = delta_time
 leer teclas y actualizar estado
 calcular M, V, P y MVP
 limpiar color y profundidad
 enviar uniforms y dibujar malla
 dibujar HUD sin depth test
 intercambiar buffers y procesar eventos

El depth test conserva el fragmento más cercano en cada píxel. El doble buffer evita mostrar una imagen a medio dibujar.

VERTEX SHADER

Una posición transformada

Un shader es un programa que ejecuta la GPU. El de vértices recibe aPos, calcula la posición clip con MVP y transmite la posición local como v_position.

RASTERIZACIÓN

De superficie a muestras

OpenGL determina qué muestras de pantalla cubre cada triángulo e interpola los datos de sus vértices, corrigiendo la perspectiva. Así cada fragmento recibe su posición local.

FRAGMENT SHADER

Un candidato a píxel

Calcula un color por fragmento. Fragmento no significa píxel final: varios triángulos pueden cubrir el mismo lugar. Las pruebas de profundidad determinan qué superficie queda visible.

Qué hace GLFW, y qué no. GLFW proporciona ventana, contexto y eventos. No interpreta OBJ, no triangula, no calcula matrices y no decodifica PPM. Esas responsabilidades son locales al proyecto.
02 /

El objeto no es
una lista de píxeles.

Es una lista de puntos y una receta para conectarlos. Antes de hablar de shaders, hay que entender esa receta.

V / POSICIÓN

Vértice

Un punto en el espacio: (x, y, z). No tiene área. Tres floats consecutivos representan una posición en mesh.vertices.

v 1.0 0.0 2.0
→ [1.0, 0.0, 2.0]
F / CONECTIVIDAD

Cara

Un contorno ordenado de vértices. Una cara puede tener tres, cuatro o más esquinas. El orden define su orientación, o winding.

f 1 2 3 4
→ un cuadrilátero
I / REFERENCIA

Índice

El número que apunta a un vértice. Permite compartir posiciones sin copiarlas por cada triángulo. El OBJ empieza en 1; el EBO empieza en 0.

OBJ: 1 → EBO: 0
offset del punto = índice × 3

De una cara a dos triángulos.

Un triángulo une tres puntos no colineales y define un plano. Nuestra llamada de dibujo usa GL_TRIANGLES: cada grupo de tres índices describe una primitiva independiente.

Un cuadrilátero necesita dos triángulos y seis índices, pero sigue pudiendo compartir sus cuatro posiciones originales. El buffer de índices no contiene coordenadas: contiene referencias.

v_count = 4 · floats = 12
i_count = 6 · triángulos = 6 / 3 = 2

La diagonal es una decisión de triangulación. En este cuadrado ambas diagonales son válidas.

Dos pasadas, una reserva. parse_obj cuenta vértices y suma 3 × (n − 2) índices por cara, reserva memoria y vuelve al inicio con rewind para rellenarla. Admite índices de posición positivos; no implementa los índices relativos negativos del formato OBJ.
03 /

Cortar sin cambiar
la silueta.

Triangular no es simplificar el objeto. Es expresar la misma superficie con las primitivas que utiliza la llamada de dibujo.

CONCEPTO / NO ES EL ALGORITMO ACTUAL

Abanico: una esquina, muchas diagonales.

Elegimos v0 como ancla y generamos (v0, vi, vi+1) para i = 1 ... n−2. Es sencillo, rápido y suficiente para polígonos convexos.

En un polígono convexo, cualquier segmento entre sus puntos queda dentro del polígono. Por eso las diagonales del abanico no cruzan el exterior. Coste: O(n).

4 esquinas → 2 triángulos
5 esquinas → 3 triángulos
8 esquinas → 6 triángulos
No confundir con GL_TRIANGLE_FAN. Aquí hablamos de generar índices en CPU; Scop dibuja con GL_TRIANGLES, independientemente del método que produjo esos índices.

IMPLEMENTACIÓN / BONUS OBJ COMPLEJOS

Ear clipping: quitar una oreja válida.

Una oreja es un triángulo formado por tres esquinas consecutivas que puede recortarse sin alterar el resto del contorno.

  1. Calcular una normal de Newell y proyectar la cara 3D a un plano 2D dominante.
  2. Calcular el área con signo para conocer el winding: horario o antihorario.
  3. Probar (anterior, actual, siguiente). Su giro debe ser convexo respecto al winding.
  4. Comprobar que ningún otro vértice activo está dentro o en el borde del triángulo.
  5. Emitir sus tres índices y retirar solo la esquina actual de la lista activa. Repetir; emitir el último triángulo.

La lista polygon[] contiene posiciones dentro de la cara, no coordenadas nuevas. El algoritmo mantiene las posiciones originales de la malla.

¿Es convexo?

cross2D(A,B,C) =
(Bx−Ax)(Cy−Ay)
− (By−Ay)(Cx−Ax)

El código multiplica por winding y exige un resultado mayor que 1e-6. Así no depende de que el contorno venga en un único sentido.

¿Contiene otro punto?

point_in_triangle hace tres pruebas de lado con cross_2d. Si el punto queda en el mismo semiplano interior de las tres aristas, bloquea la oreja.

Se incluye el borde con tolerancia −1e-6: una diagonal que pasa por otro vértice no se acepta como corte.

¿Y si no hay oreja?

Se devuelve error, sin inventar un abanico de respaldo. Hay una guarda de n × n iteraciones y rechazo de área proyectada casi nula.

Esta búsqueda ingenua tiene coste peor caso O(n³). Es una elección práctica para caras pequeñas, no para polígonos gigantes.

El bonus tiene alcance concreto. Resuelve caras simples cóncavas mediante proyección. No hay soporte general de agujeros, contornos auto-intersectados ni triangulación garantizada de caras no planas. El parser rechaza caras con 64 o más esquinas; el máximo efectivo es 63. La etiqueta de consola indices (base 0, fan) es antigua: triangulate_face usa ear clipping.
04 /

Una dirección
perpendicular.

Una normal no es otro punto del objeto. Es un vector que describe la orientación de una superficie.

NORMAL DE UN TRIÁNGULO

Dos aristas, un producto vectorial.

Con tres posiciones A, B y C obtenemos dos aristas u = B − A y v = C − A. El producto vectorial u × v es perpendicular a ambas.

N = (uy vz − uz vy,
     uz vx − ux vz,
     ux vy − uy vx)
n = N / sqrt(Nx² + Ny² + Nz²)

Normalizar conserva la dirección y hace la longitud igual a 1. Intercambiar B y C invierte la normal. Si los tres puntos son colineales, el producto vale cero y no hay una normal definida.

Ejemplo: A=(0,0,0), B=(1,0,0), C=(0,1,0) → n=(0,0,1).

Newell: escuchar todo el contorno.

Si una cara tiene muchas esquinas, elegir solo las tres primeras puede ser mala idea: pueden ser colineales. Newell acumula una contribución por cada pareja consecutiva, incluyendo la última con la primera.

Nx += (yi − yj)(zi + zj)
Ny += (zi − zj)(xi + xj)
Nz += (xi − xj)(yi + yj)
j = (i + 1) % n

En dominant_projection no hace falta normalizar: solo se compara |Nx|, |Ny|, |Nz|. Se elimina la coordenada del componente más grande para proyectar sobre el plano donde la cara conserva mejor su área.

Para el fixture cóncavo: N = (0, 0, 5). Se descarta Z, se usa XY y el área con signo es +2.5.

DE 3D A 2D / SIN BORRAR EL OBJETO

Proyección dominante

Mayor componentePlano utilizado
|Nx|YZ → (y,z)
|Ny|XZ → (x,z)
|Nz|XY → (x,y)
Área = ½ Σ(xi yj − xj yi)
winding = área > 0 ? +1 : −1

Solo se proyecta para las pruebas geométricas del corte. Los índices emitidos siguen apuntando a los vértices 3D originales.

DOS NORMALES / DOS RESPONSABILIDADES

CPU: orientar el corte.

La normal de Newell sirve para elegir el plano de triangulación. No se guarda en un VBO de normales ni se envía como atributo vn.

GPU: orientar la textura.

normal = normalize(cross(
  dFdx(v_position), dFdy(v_position)
));

El shader calcula diferencias de la posición interpolada entre fragmentos vecinos. Esa normal, en espacio local, determina pesos triplanares y el modo de depuración.

Color de normales = normal × 0.5 + 0.5
(−1 ... +1) → (0 ... 1) → RGB

N activa colores de normales; B vuelve al resultado habitual. No es iluminación ni un suavizado por vértice. La normal derivada tiene una orientación ligada al orden de los derivados en pantalla; no es necesariamente la normal exterior del OBJ. El valor absoluto usado en triplanar elimina la importancia de su signo para los pesos.

05 /

Girar sobre sí mismo.
No alrededor del mundo.

El centro de la malla, el orden de las matrices y el tiempo entre frames explican todo el movimiento.

Primero: llevar el centro al origen.

center_mesh encuentra mínimos y máximos en X, Y y Z: la caja envolvente alineada con los ejes, o AABB.

centro = (mínimo + máximo) / 2
punto centrado = punto original − centro

Ejemplo: una caja de (2,1,−1) a (4,3,1) tiene centro (3,2,0). Al restarlo, su caja pasa a (−1,−1,−1) ... (1,1,1).

Esto no calcula el centro de masa ni la media de los vértices. Tampoco escala el modelo: objetos grandes siguen siendo grandes. Se hace una vez, antes de subir las posiciones a la GPU.

LAB. C / EL PIVOTE IMPORTACENTRADO

Vista 2D del principio 3D. Sin centrar, también gira el desplazamiento del objeto y aparece una órbita. El origen amarillo no se mueve.

ORDEN EXACTO / VECTORES COLUMNA

La derecha actúa primero.

R = Rz × Ry × Rx
M = T × R
MVP = P × V × M
clip = MVP × (x, y, z, 1)

Se rota X, después Y, después Z y finalmente se traslada. En T × R, la traslación no gira: mover el objeto no cambia su pivote local.

mat4_mul implementa C[fila,col] = Σ A[fila,k] B[k,col]. El almacenamiento es column-major: m[col * 4 + fila]. La matriz se envía con GL_FALSE, sin transponer.

ROTACIÓN Y COORDENADAS HOMOGÉNEAS

¿Por qué una matriz 4 × 4?

El cuarto componente permite expresar traslación y perspectiva en la misma cadena de multiplicaciones. Un punto tiene w=1; una dirección se representa con w=0, de modo que no recibe traslación.

Giro Y:
x' = cos(θ)x + sin(θ)z
y' = y
z' = −sin(θ)x + cos(θ)z

Girar en X afecta a YZ; girar en Y afecta a XZ; girar en Z afecta a XY. Las rotaciones no conmutan: cambiar su orden cambia el resultado.

M / Modelo

Coloca el objeto en el mundo. Composición de rotaciones y traslaciones controladas por teclado. mat4_scale existe, pero el loop actual no aplica escala.

V / Vista

T(0,0,−5) equivale a una cámara en Z=5 mirando hacia −Z. No se mueve la cámara con las teclas: se mueve la malla.

P / Perspectiva

FOV vertical de 60°, aspect del framebuffer, near=0.1 y far=100. OpenGL divide las coordenadas clip por w: lo lejano parece más pequeño.

El logo 42 gira por una regla explícita.

No es una propiedad especial del OBJ ni una animación guardada en el modelo. En main se comprueba si la ruta contiene la subcadena "42.obj".

is_42_logo = strstr(obj_path, "42.obj") != NULL
si es 42: rotation_y += delta_time × 0.8

Se añaden 0.8 radianes por segundo en Y, incluso sin pulsar teclas. La misma bandera activa tonos grises por triángulo con u_gray. Las rotaciones manuales siguen sumándose.

Es una detección por nombre de ruta, no por contenido: cualquier ruta que contenga esa subcadena recibe el tratamiento de demostración. Todos los modelos, no solo el 42, pasan por center_mesh.
TIEMPO / NO NÚMERO DE FRAMES

La velocidad no depende de los FPS.

Δt = t_actual − t_anterior
Δθ manual = eje × Δt × 1.8
Δposición = eje × Δt × 1.5

A 60 FPS, el giro automático suma aproximadamente 0.0133 rad/frame; a 30 FPS, 0.0267. En ambos casos, un segundo acumula 0.8 rad.

key_axis devuelve −1, 0 o +1. Pulsar ambas direcciones se cancela. Los toggles T, G y H detectan el flanco de pulsación, no se alternan en cada frame.

Tres planos por superficie.

Desde una imagen RGB sin compresión hasta una textura que se adapta a la orientación de cada triángulo.

DECODIFICADOR PROPIO

PPM: una imagen sin misterio.

Portable Pixmap almacena ancho, alto, valor máximo y una secuencia de colores RGB. No es geometría, no guarda caras y no incluye canal alpha. Es la fuente de colores de la textura.

TipoCabeceraDatos
P3Texto ASCIINúmeros decimales: 255 0 0.
P6Texto ASCIIBytes binarios: FF 00 00.

load_ppm soporta ambos y exige max_value = 255. Una imagen W × H ocupa W × H × 3 bytes de datos RGB. read_ppm_token salta espacios y comentarios # al leer tokens.

En P6 se consume el separador de cabecera y se leen los bytes con fread; en P3 se interpretan los canales con strtol. La textura se sube como GL_RGB / GL_UNSIGNED_BYTE y la copia CPU se libera con free_image.

LAB. D / MICROIMAGEN P33 × 2 = 18 BYTES RGB
P3          # formato ASCII
3 2         # ancho y alto
255         # máximo por canal
255 0 0     0 255 0     0 0 255
255 255 0   255 0 255   0 255 255
Selecciona un píxel para localizar sus tres bytes.

Los 18 bytes son los canales decodificados. El archivo P3 ocupa más, porque también contiene texto, cabecera y separadores. Cada fila de esta imagen mide 9 bytes.

Una sutileza de OpenGL. El código actual no cambia GL_UNPACK_ALIGNMENT (por defecto, 4). Una fila RGB cuyo tamaño no sea múltiplo de cuatro requiere ajustar esa alineación o añadir padding antes de subirla. El microejemplo explica el formato; no promete que cualquier ancho PPM se suba correctamente con la configuración actual.
BONUS / REDUCIR STRETCHING

Triplanar: no hay un único plano bueno.

Proyectar toda la textura sobre XY funciona en superficies que miran a Z. En una pared perpendicular a ese plano, las coordenadas se comprimen y la imagen se estira.

El shader toma tres muestras por fragmento: XY, XZ e YZ, usando v_position local, multiplicada por 0.45. Como son coordenadas del objeto, la textura acompaña su giro y traslación.

pesos = abs(normal)^4
pesos /= pesos.x + pesos.y + pesos.z
Ctex = Cxy × peso.z
    + Cxz × peso.y + Cyz × peso.x

Una normal cercana a Z favorece XY; cercana a Y favorece XZ; cercana a X favorece YZ. La potencia 4 concentra la mezcla en el plano dominante y reduce la zona de mezcla.

La textura usa filtrado lineal. No se generan mipmaps; el wrapping GL por defecto es REPEAT. Esta técnica reduce stretching, pero no sustituye un desplegado UV artístico ni elimina toda costura.

Simulación de la fórmula real de pesos. Los colores identifican planos; no son tres imágenes distintas en Scop.

De color a textura, sin salto.

gl_PrimitiveID proporciona un identificador constante por triángulo. El shader genera colores con senos del ID; para el logo utiliza 0.25 + 0.06 × (id mod 8) como tono gris. No es una simulación de luz.

La tecla T invierte el objetivo, 0 o 1. El factor se aproxima a ese objetivo a razón de 2 × delta_time y se limita al intervalo [0,1]. Un recorrido completo tarda aproximadamente 0.5 segundos.

resultado = mix(color, textura, factor)
= (1 − factor) × color + factor × textura

El modo N sobrescribe esa mezcla con el color de la normal. G cambia la rasterización a líneas con glPolygonMode: muestra aristas de triángulos, incluidas las diagonales creadas al triangular.

ALCANCE / SIN EXAGERAR

No es una prueba total

Los tests no validan todo el render, todos los OBJ ni el cargador PPM. Los bonus se demuestran también de forma visual; una prueba de unidad no reemplaza el recorrido interactivo.

V / I / F en el HUD. V cuenta posiciones originales; I cuenta índices del EBO; F muestra i_count / 3, es decir, triángulos renderizados, no las caras originales del OBJ. El fixture cóncavo tiene una cara de entrada y muestra F=3.

Preguntas que conviene saber responder.

¿Por qué no usar siempre el abanico?

Porque un contorno cóncavo puede tener diagonales desde el ancla que salen de la cara. En nuestro fixture, el abanico desde 0 genera un triángulo grande que cubre el entrante, y otro con orientación opuesta que se solapa. Ear clipping selecciona diagonales válidas mediante convexidad y contención.

¿Las caras originales conservan un color único?

No necesariamente. El color se genera con gl_PrimitiveID por triángulo emitido. Dos triángulos de una misma cara OBJ pueden tener colores distintos. El programa no almacena una correspondencia entre ID de triángulo y cara original.

¿Hay iluminación, materiales o normales importadas?

No hay un modelo de iluminación, ni lectura de materiales MTL ni uso de vn/vt. Los colores proceden del ID de primitiva; las normales se calculan con derivados del fragment shader y la textura se proyecta triplanarmente.

¿Qué pasa con OBJ degenerados o entradas no soportadas?

El parser tiene restricciones concretas: registros v/f reconocidos con un espacio tras la letra, índices positivos en rango, buffer de línea de 1024 bytes y caras de hasta 63 esquinas efectivas. La tolerancia geométrica es absoluta, no adaptada a escala. No debe presentarse como un importador universal ni como un validador exhaustivo de ficheros arbitrarios. Las posiciones referenciadas deben estar disponibles cuando se procesa la cara.

¿El centrado garantiza que cualquier modelo quepa en pantalla?

No. Restar el centro AABB solo cambia la posición local. El proyecto no ajusta automáticamente escala, distancia de cámara ni encuadre según el tamaño de la malla.

¿Cuál es la contrapartida del triplanar?

Tres muestras de textura por fragmento y una mezcla de pesos, frente a una sola muestra en un UV mapping sencillo. Puede producir transiciones o reflejos visuales según las orientaciones, y no permite colocar con precisión una etiqueta o un rostro como un UV diseñado a mano.
